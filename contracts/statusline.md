## Purpose {#purpose}

`statusline` — статус-лайн Qoder CLI: единственный скрипт `statusline-command.sh` (POSIX sh), который CLI вызывает на каждом обновлении, передавая JSON сессии в stdin. Скрипт рендерит одну компактную строку ANSI-цветных сегментов (модель и размер контекстного окна, процент использованного контекста, процент оставшихся кредитов планового пула, счётчик живых сабагентов, git-изменения working tree, ветка, путь) с graceful-деградацией при отсутствии данных.

**Решаемая проблема.** Пользователю CLI нужна плотная оперативная сводка состояния сессии, не занимающая экран: расход контекста, остаток кредитов подписки, активность параллельных агентов, состояние репозитория. Штатного статус-лайна такой плотности нет; сторонние решения тянут зависимости.

**Стороны.**

- Пользователь/оператор: видит строку в CLI; правит компонент через контрактный цикл.
- Харнесс Qoder CLI: вызывает скрипт, передаёт session JSON в stdin, печатает stdout.
- Репозиторий `~/dev/qoder-cli-statusline`: источник правды; его `AGENTS.md` задаёт политику (repo-first, contract-first, запрет blanket pull, conventional commits).
- Рантайм `~/.qoder-cn/statusline-command.sh` (доступен через симлинк `~/.qoder`): разворачиваемая копия; синхронизация — `sync.sh` (`status` / `push` / `pull [--confirmed statusline]`).
- Удалённый репозиторий (`origin`, github.com/al-siv/qoder-cli-statusline): точка публикации; публичный текст репо — английский.

Контракт — источник истины о компоненте: гомогенизированная текущая спецификация, единственный нормативный источник. **Принцип восстановимости:** секция Specification несёт полный нормативный состав скрипта, так что `statusline-command.sh` восстановим из контракта практически как он есть; скрипт — рендер контракта для рантайма. Эпизоды изменений и их замыслы — в журнале [statusline-journal.md](statusline-journal.md).

## Invariants {#invariants}

INV-1: Компонент — один файл `statusline-command.sh` в корне репо, POSIX sh (`#!/bin/sh`); зависимости — только `jq` (обязателен) и `git` (опционален в рантайме: без него деградируют git-сегменты). Входные данные приходят из stdin харнесса и из рабочего дерева репозитория; файлы сессии читаются только по путям из stdin, производный кэш разбора не является источником данных. Сетевых запросов компонент не делает, учётные данные и конфигурацию CLI не читает (основание — QA-2).

INV-2: Репозиторий — единственный источник правды; рантайм получает правки только через `./sync.sh push`, рантайм-правки входят только через контролируемый adopt.

INV-3: Классификация предшествует действию: неклассифицированный дрифт не adoptится (bare `pull` пишет отказ, не файлы).

INV-4: Деградация без падения: любое отсутствующее поле/команда/файл — сегмент пропускается или берётся fallback, скрипт не прерывается; вывод байт-точен (ESC-коды хранятся как реальные байты, финальный `printf '%s'` не реинтерпретирует содержимое сегментов).

INV-5: Pre-push hook не обходится: блокировка пуша возвращает к устранению нарушения, а не к отключению/игнорированию проверки.

INV-6: Восстановимость: контракт исчерпывающе описывает поведение скрипта (форматы, пороги, fallback'и, алгоритм кэша), реконструкция по контракту не требует чтения старой реализации.

## Specification {#specification}

Состав ниже — полный нормативный состав компонента; реконструкция `statusline-command.sh` выполняется по этому тексту.

**Вход и парсинг.**

- Вход: session JSON из stdin; весь разбор — один вызов `jq`, поля соединяются `\n` (перенос строки, а не табуляция: пустые поля должны выживать при разборе).
- Поля и fallback'и:
  1. `model.display_name // .model.id // ""` — имя модели.
  2. Размер окна: при `context_window.context_window_size` — компактная форма: `>= 1000000` → `(size/1e6*10 | round)/10`, хвост `.0` отбрасывается, суффикс `M` (пример: `1M`, `1.5M`); иначе `round(size/1000)` с суффиксом `k` (`400k`); поля нет → пусто.
  3. ctx: `context_window.used_percentage | round`; нет → `(100 - remaining_percentage) | round`; нет обоих → пусто.
  4. cr — процент **оставшихся** кредитов планового пула. Перед разбором полей в той же единственной `jq`-программе входное `(.credits.user_quota? // {}) | if type == "object" then . else {} end` связывается с `$q`, и уже из `$q` берутся `total` и `remaining`: при числовых обоих и `total > 0` → `round(remaining / total * 100)` с clamp в диапазон 0..100; иначе пусто. Привязка с приведением типа обязательна: ошибка индексирования внутри `jq` обрывает весь разбор и снимает сразу все сегменты, а не один; `// {}` закрывает отсутствующее поле, `null` и пустой поток от `?`, а проверка типа — неиндексируемые значения (массив, строка, число). Поле `percentage` не используется (в payload оно про *использованное*: research, п. 4); `unit` не рендерится (отношение безразмерно); суммарный `total_remaining` не рендерится (смешивает пулы, см. «Сборка строки»).
  5. `workspace.current_dir // ""`.
  6. `transcript_path // ""`.
- Ошибки `jq` подавляются (`2>/dev/null`); пустой/битый вход — все поля пусты, скрипт продолжает работу.
- Пустой `current_dir` заменяется на `pwd`.

**Git-сегменты.**

- Репозиторий определяется `git -C "$dir" rev-parse --is-inside-work-tree`; вне репо — флаг `nogit`.
- Ветка: `rev-parse --abbrev-ref HEAD`.
- Дифф: `added`/`removed` = сумма numstat по (а) `git diff HEAD --numstat` (tracked) и (б) untracked: `ls-files --others --exclude-standard -z | xargs -0 git diff --no-index --numstat -- /dev/null` (батчинг под ARG_MAX); агрегирование `awk '{a+=$1; r+=$2} END {printf "%d %d", a+0, r+0}'`. Это изменения working tree, а не счётчики сессии.
- Репозиторий без коммитов: `rev-parse --verify -q HEAD` не проходит → флаг `nocommits` (на unborn HEAD `--abbrev-ref` печатает литерал `HEAD`, который не должен маскироваться под ветку).

**Путь.** `$HOME` → `~`; `$HOME/...` → `~/...`.

**Счётчик живых сабагентов (AG).** Блок активен только при непустом и читаемом `transcript_path`; иначе пропускается целиком, включая реестр, и AG не показывается. Два источника, объединяются **max** (не сумма: форграунд-агент виден обоим источникам одновременно).

- Источник A — парные записи транскрипта (JSONL): `assistant`-события с `tool_use` имени `Agent` (метка `U <id>`) и `user`-события с `tool_result` (метка `R <tool_use_id>`); живые = U без соответствующего R.
- Инкрементальный кэш: каталог `${TMPDIR:-/tmp}/qoder-statusline-ag` (`mkdir -p`, `chmod 700`); имя файла кэша — первое поле `cksum` пути транскрипта (CRC) с суффиксом `.cache`; первая строка кэша — разобранный байт-офсет, далее — открытые id. При обновлении: если кэш есть, его первая строка числовая и офсет ≤ размера файла — разбирается только дописанный хвост (`tail -c +offset+1`); нечисловая первая строка или офсет > размера — инвалидация и полный разбор. Незавершённая последняя строка (без `\n`) откладывается на следующий проход; `jq -R 'fromjson?'` пропускает битые строки. Открытые id: объединение закэшированных и новых `U` за вычетом всех `R` (уникальные множества: `sort -u` + разность `comm -23`; пустые id отбрасываются). Кэш переписывается каждый проход (новый офсет + открытые id). Распарсенные поля читаются шестью `IFS= read -r` из heredoc под гардом непустого результата jq (механика, сохраняющая пустые поля).
- Источник B — реестр `${transcript%.jsonl}/subagents/task-*.json` (обход рекурсивный, `find`): live-статус есть у всех агентов, включая фоновые (у фоновых `tool_result` пишется при запуске, источник A их не видит). Разбор per-file slurp (`jq -Rs 'fromjson? | select(type=="object") | select(.status ∉ [completed,cancelled,canceled,failed,stopped]) | .taskId // .agentId // "x"'`, статус отсутствует или null — файл считается live), подсчёт строк; per-file — чтобы один битый/полупрозаписанный файл не скрыл остальных (батч-разбор оборвал бы весь батч).
- Итог `agents = max(A, B)`; сегмент показывается только при `agents > 0`.

**Цвета.** ESC-байты создаются `printf '\033[…m'` и хранятся в переменных (финальный вывод байт-точен): модель — cyan (36); путь — blue (34); `+added` — green (32); `-removed` — red (31); ветка не-main — bright magenta (95); `NO GIT!` — bold red (`1;31`); `no commits` и AG — yellow (33); разделители — gray (90); маркер левой границы `❯` — светлый серый (256-цветная палитра: `38;5;250`); reset — `0`. На терминалах без 256-цветной палитры код маркера игнорируется — маркер берёт цвет по умолчанию, строка не ломается. Цвет ctx по порогам использованного процента: ≤50 — green (32), ≤80 — yellow (33), выше — red (31). Цвет cr — инверсия по смыслу (цвет растёт по мере исчерпания остатка): остаток ≥50 — green (32), ≥20 — yellow (33), ниже — red (31); переменная `C_CR` вычисляется тем же механизмом порогов, что `C_CTX`, и остаётся пустой при отсутствии значения.

**Сборка строки.** Префикс — светло-серый маркер левой границы `❯` (шеврон; отрывает имя модели от левого края терминала). За маркером — обычный пробел перед первым непустым сегментом; серый разделитель ` | ` ставится только между сегментами, после маркера его нет. При пустом составе сегментов маркер выводится один, без хвостового пробела. Сегменты в фиксированном порядке, пустые пропускаются:

1. Модель (cyan) + пробел + окно (текст окна бесцветный), окно только при непустой модели.
2. `ctx N%` цветом по порогам.
3. `cr N%` (остаток плановых кредитов) цветом по порогам; сегмент отсутствует при пустом значении.
4. `AG n` (yellow), только при n > 0.
5. `+a/-r`: `+a` зелёным, `/` серым, `-r` красным; сегмент скрыт при a=0 и r=0 (чистое дерево).
6. Ветка: `no commits` (yellow) имеет приоритет; иначе `main` — cyan, иная ветка — bright magenta; вне репо — `NO GIT!` bold red.
7. Путь (blue, с `~`-сокращением) — всегда.

Два метра расхода (`ctx`, `cr`) стоят рядом и читаются как одна пара: сначала окно текущей модели, затем кредиты планового пула; суммарный остаток всех пулов (`total_remaining`) не рендерится — он смешивает план, аддон и org-пакет.

**Защитная механика и байт-точность.** Все числовые значения, получаемые из внешних команд и файлов (`wc -c`, подсчёты кэша и реестра; с padding'ом `wc` на macOS — `tr -d ' '`), гейтятся паттерном `''|*[!0-9]*` с fallback 0. Значение `cr` — выход внешнего процесса (`jq`), и хотя clamp и округление выполняются внутри `jq`, оно гейтится тем же паттерном с fallback «пусто»: нечисловой вывод даёт пустое поле и скрытый сегмент, а не сравнение с мусором в порогах цвета. Временные файлы прохода (`chunk`, `res`, `open`) — с PID-суффиксом `.$$` в каталоге кэша, удаляются после каждого прохода. Каждый окрашенный элемент — ESC-код, содержимое, reset, включая светло-серый маркер `❯` и серый разделитель ` | ` (reset — часть каждого элемента).

**Вывод.** Один `printf '%s'` собранной строки, без завершающего перевода строки.

Out of scope (сознательно не в компоненте):

- Конфигурация/темы: набор и порядок сегментов фиксированы, пользовательских настроек нет (компонент — один скрипт без зависимостей, INV-1).
- Repo-механика (sync, hook, релиз, пин родителя): не принадлежит контракту компонента (boundary-правило `contracts/AGENTS.md`).

## Acceptance gates {#gates}

GATE-1 — полнота спецификации: каждая семантическая точка скрипта (парсинг всех полей входа с fallback'ами, компактные формы окна, git-статистика с untracked и unborn HEAD, `~`-сокращение, два источника AG с инкрементальным кэшем и инвалидацией, все цвета и пороги ctx и cr, порядок сегментов и маркер левой границы, байт-точный вывод) покрыта Specification; скрипт восстановим из контракта с нуля. Verify: построчная сверка скрипта против контракта при создании контракта (2026-08-14) и при каждой правке состава сегментов.

GATE-2 — харнесс активирован и гейты проходят: `./sync.sh status` чист, `.hooks/pre-push` завершается 0, `core.hooksPath` указывает на `.hooks`. Verify: вывод команд при установке харнесса (CHANGE-2026-08-14-a).

GATE-3 — аудит полноты baseline: построчная сверка скрипта против контракта (своя + независимая, агент без контекста сессии). Verify: CHANGE-2026-08-14-b.

GATE-4 — живой вход подтверждает используемое поле: сегмент, добавленный по непрописанному входному полю CLI (поле stdin, задокументированное здесь только по разбору бинарника), считается работающим только после наблюдения непустого значения в строке живой сессии; статический разбор устанавливает форму поля и наличие кода, но не кадр. Verify: строка статус-лайна новой сессии CLI с отображаемым `cr N%`.

## Risks {#risks}

RISK-1 — Дрейф рантайма: живая правка скрипта в сессии минует репо и теряется/закрепляется как чужая. Mitigation: repo-first + pre-push гейт 1 + гейтед pull (INV-2, INV-3).

RISK-2 — Дрейф контракт↔скрипт: правка скрипта без контракта или без обновления спецификации. Mitigation: RULE-contract-first + RULE-reconstructability + pre-push гейт 2 (контракт, журнал, IDX).

RISK-3 — Конфликт со скиллом `publish-statusline` родительского репо: разрешён (QA-1, resolved) — скилл переведён на repo-first модель этого репо (коммит родителя `b264d08`, EP-2). Остаточный риск — дрейф скилла при его будущих правках в цикле родителя. Mitigation: пин-процедура `harness-check.sh` отслеживает изменения харнесса родителя; при расхождении — адаптация по `AGENTS.md`.

RISK-4 — Поле `credits` непрописано: CLI не документирует состав stdin статус-лайна, а снимок квоты существует только при одновременно настроенной статус-лайн-команде, неотключённых хуках и доступной CLI квоте (неаутентифицированный процесс, ошибка API, enterprise-представление использования, где снимок инвалидируется). Исчерпание кредитов различимо от отсутствия поля: при нулевом остатке сегмент показывает `cr 0%` красным, при отсутствии поля сегмента нет. Слепое место остаётся при `total ≤ 0` и при нечисловых или отсутствующих `total`/`remaining` — форму, которую нормализатор CLI не производит (`remaining` там выводится как `max(total − used, 0)`, даже если сервер его не прислал: research, п. 4). Mitigation: отсутствие значения скрывает сегмент, а не рисует ноль или устаревшее число (INV-4); форма и версия источника зафиксированы в research; GATE-4 требует живого подтверждения после правок CLI.

## Q&A {#qa}

QA-1 — Скилл `publish-statusline` (репо `~/dev/qoder-skills`) объявлял живой файл `~/.qoder/statusline-command.sh` источником правды и предписывал императивные коммит-сообщения без conventional-префикса, что противоречило политике этого репо (repo-first, conventional commits). Status: resolved (2026-08-17). Decision: скилл доработан в контрактном цикле родителя (backfill-контракт + журнал, EP-2 адаптации, коммит родителя `b264d08`): источник правды — этот репо, деплой рантайма — `./sync.sh push` этого репо, adopt — `pull --confirmed statusline`, сообщения — conventional, перед пушем `./harness-check.sh check` чист. Противоречия больше нет; скилл — актуальный транспорт публикации, согласованный с политикой этого репо.

QA-2 — Где компонент берёт число кредитов: вариант «сам запросить `GET /api/v2/quota/usage`» отвергнут, вариант «взять из stdin» принят. Status: resolved (2026-09-19). Decision: только stdin (см. [../analysis/2026-09-19-statusline-credits-payload-research.md](../analysis/2026-09-19-statusline-credits-payload-research.md)). Прямой запрос означал бы сеть и вызов токена на каждом обновлении строки, чтение зашифрованного хранилища `~/.qoder-cn/.auth` и новую зависимость — против INV-1 и его границы входных данных; при этом CLI уже держит снимок квоты (кэш 15 с) и передаёт его тому же скрипту в поле `credits`. Цена решения: свежесть числа равна свежести снимка харнесса, который сам появляется только при доступной CLI квоте; собственной сетевой активности и доступа к учётным данным компонент не заводит.
