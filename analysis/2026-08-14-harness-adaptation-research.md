# Адаптация харнесса qoder-skills к репозиторию qoder-cli-statusline

Дата: 2026-08-14. Статус: принято (решение пользователя: repo-first).

## Что изучено

Харнесс родительского репо `~/dev/qoder-skills`:

1. Корневой `AGENTS.md` — политика: repo-first, «не пушить при нарушениях», «чужой дрифт — не свой коммит», conventional commits, модель именования скиллов, contract-first цикл, правила сплита методологии/обвязки, отношения с соседними репо.
2. `contracts/AGENTS.md` — контрактная система: один постоянный контракт на скилл, восстановимость, правила нумерации скоупов/гейтов, аддитивная история, канон IDX, обsolescence.
3. `.hooks/pre-push` — три гейта: drift репо↔рантайм; контракт+IDX на каждый скилл; двунаправленная сверка статусов скоупов IDX↔контракт.
4. `sync.sh` — status/push/pull с гейтед pull (`--confirmed` с явной выборкой, bare pull только предупреждает).
5. `analysis/` — исследования, на которые ссылаются контракты через `refs`.

## Отличия проектов

| Ось | qoder-skills | qoder-cli-statusline |
| --- | --- | --- |
| Компоненты | множество скиллов (каталог + SKILL.md) | один артефакт `statusline-command.sh` |
| Рантайм | `~/.qoder/skills/` (каталоги) | один файл `~/.qoder-cn/statusline-command.sh` |
| Направление правды | repo-first (sync push) | исторически runtime-first (скилл publish-statusline); решение — repo-first |
| Именование | модель «глагол + существительное» | не применима (один компонент) |
| Выборка pull | по именам скиллов, `--all` запрещён при смешанном дрифте | один объект — выборка вырождается, гейт сохранён |

## Решения

1. **Repo-first** (подтверждено пользователем): репо — источник правды; деплой в рантайм — `./sync.sh push`; рантайм-правка — исключение через гейтед `pull --confirmed statusline`.
2. **Граница объекта** — контракт на компонент (`contracts/statusline.md`): объект контракта — статус-лайн (компонент), а не скилл; маппинг артефакт↔контракт объявлен в `OBJECTS` хука.
3. **Гейты хука** — три гейта родителя перенесены без редукции: drift, contract-per-object, IDX-status-sync. BACKLOG отсутствует по построению.
4. **Связка с родителем — процедурная, не ссылочная** (уточнение пользователя): декларация «принципов родителя» создавала бы неуправляемую жёсткую зависимость, а категории «принципы» в AGENTS.md родителя нет. Вместо этого — пин: `.harness-pin` хранит sha256 файлов харнесса родителя (`AGENTS.md`, `contracts/AGENTS.md`, `.hooks/pre-push`) и дату последней адаптации этого репо; git-состояние родителя и его `sync.sh` (механика синхронизации скиллов) не фиксируются — к этому проекту отношения не имеют. `./harness-check.sh check` — периодическая сверка (перед пушем и по запросу); при расхождении — процедура адаптации (разбор изменений родителя → перенос/отклонение с записью → локальные правки → перепись пина). Механики остаются локальными; репо родителя этот репо не гейтит и не зеркалирует.
5. **Языки** — проза контрактов и политик русская (рабочий язык родителя), LLM-разметка и README (публичный) — английские.

## Открытые конфликты (переданы в контракт, QA-1)

- Скилл `publish-statusline` в родительском репо объявляет живой файл источником правды и предписывает императивные коммит-сообщения без conventional-префикса — противоречит новой политике этого репо. Скилл в BACKLOG родителя (без контракта), правка возможна только через backfill-контракт в цикле родителя; до этого скилл трактуется как legacy-транспорт.
